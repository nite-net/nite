# Peer dependency version mismatch

A package declares a peer dependency (a package it expects your app to provide, such as `react`
for a component library), and the version installed for your app is outside the range it asks
for. NiteFx installs peers that are missing, but when one is already installed at another version
it keeps that version and carries on, rather than failing the install.

Often nothing breaks: peer ranges are frequently stricter than they need to be. When something
does break, it shows up as errors from that package at run time, typically because it calls an API
the installed version does not have.

## How to fix it

- Update the package that logged it with `nite update <name>`: a newer release may accept your version.
- Or move the peer to a version in the range with `nite add <name>@<version>`.
- If everything works, you can leave it.
